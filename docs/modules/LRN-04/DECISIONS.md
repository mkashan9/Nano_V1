# LRN-04 decisions

## Checkpoints are content, not client behaviour

The player does not decide where to interrupt. Rows in
`public.refresh_checkpoints` do, and they are generated by
`nano_internal.plan_refresh_checkpoints` from the video's own chapter list. A
new app build cannot start interrupting videos differently, and a curator can
move a prompt without shipping code.

## Generation is a rule, editing is allowed, guardrails apply to both

`plan_refresh_checkpoints` only fires past thirty minutes, aims at ten-minute
intervals, snaps to the nearest non-protected boundary within two minutes, and
keeps five minutes between prompts. Curators can still move or delete anything,
but the same guardrails run as a trigger: too close to the edges (`NL007`),
inside a protected chapter (`NL008`), or within five minutes of another prompt
(`NL009`) are all refused. "Editors can move checkpoints" does not mean editors
can interrupt an assessment.

## A rebuild preserves hand-placed rows

`rebuild_refresh_checkpoints` deletes only rows it generated. When a generated
candidate collides with a hand-placed prompt, the collision is swallowed and
the curator's row wins. The seeded fixture exercises exactly this: the required
prompt at 1320s survives a rebuild that also wants that moment.

## Optional prompts can be silenced; required ones cannot

Classroom Mode, and the refresh-prompt preference, suppress optional prompts
only. That would be a loophole if silence also meant free credit, so the server
caps watch credit at the first unanswered required checkpoint
(`nano_internal.checkpoint_credit_gate`). A learner who hides prompts simply
stops earning progress at that point. The client mirrors the same rule so it can
explain itself before the next heartbeat lands, but the server is the authority.

## Acknowledgement is an RPC, not an insert

`checkpoint_events` has no learner-facing insert grant. Releasing a gate goes
through `public.acknowledge_checkpoint`, which re-runs
`nano_internal.assert_topic_writable`, validates the response value, and upserts
on `(user_id, checkpoint_id)`. Answering twice is the same row; a duplicated
network call cannot manufacture a second event.

## Seeking policy is enforced twice, on purpose

`no_skip_ahead` content clamps the reported position to
`watched_seconds + 30` inside `record_playback_heartbeat`, and the client stops
the scrubber at the same ceiling. The UI clamp is a courtesy so the thumb does
not snap back; the server clamp is the rule.

## SECURITY DEFINER on acknowledge_checkpoint is intentional

It writes a table learners cannot write and reads gate state across rows. Its
`search_path` is pinned, `EXECUTE` is revoked from `public` and `anon`, and it
refuses anyone who is not an active learner on a playable topic. The advisor
warning for it is expected, like the other learning RPCs.

## The prompt pauses playback

A refresh moment that talks over the video is noise. The clock stops, the
heartbeat fires so the position is not lost, and the prompt takes the companion
slot. **Take a break** leaves the video paused rather than resuming behind the
learner's back.
